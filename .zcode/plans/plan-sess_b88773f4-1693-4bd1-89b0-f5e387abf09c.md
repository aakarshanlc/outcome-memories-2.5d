## Bug fixes

1. **Projectile never stuns a free-roaming killer** — `src/entities/Projectile.js:34` checks `k.health > 0 || k.stunned > 0`, but `Killer` has no `health` property, so the condition is only true when the killer is *already* stunned. Fix: drop the broken condition so the projectile hits (damage + stun) whenever it collides with the killer.

2. **Config filename casing** — file on disk is `src/config/Mapvariables.js` but `src/maps/MapManager.js:2` imports `MapVariables.js`. Works on Windows, breaks on Linux/case-sensitive systems. Fix: `git mv` the file to `MapVariables.js` to match the import and the note's stated format.

3. **Unused `blockSink` sfx** — `MapVariables.*.sfx.blockSink` and the `Map/block_sink_1.mp3` asset exist but are never played. Fix: in `MapManager.update()`, play `Map / block_sink` when a maze block transitions into `lowering` and into `rising`. MapManager needs access to the AudioManager — it will accept it via the `update(players, killers)` call site in GameManager (pass `gameManager.audio`, or store a reference). Simplest: pass `gameManager` from GameManager's loop (`this.mapManager.update(this.players, this.killers, this)`).

4. **Fragile ability lookups** — `Player.js` reads `this.config.abilities.fly` (line ~93) and each character branch reads its ability config directly. Guard with optional chaining / defaults (`this.config.abilities?.fly?.maxCharges ?? 0`) so placeholder characters (Surv1/Surv2) or a character with missing keys can't crash the constructor.

5. **Redundant autoplay attempt** — `AudioManager` constructor calls `playMusic('menu')` before user interaction; browsers block it and UIManager immediately stops it on the main screen, producing console warnings. Fix: remove the constructor autoplay; audio starts via the existing first-interaction listener.
